# Provider-specific journal attribution and monthly Basic limit

Accepted 2026-10-22 for PIC-290. Supersedes [ADR 0002](0002-client-wide-journal-visibility.md).

Each new journal belongs to one client and one provider. Basic enrollments allow at most 10 existing entries per client/provider pair per application calendar month (currently UTC); Premium is unlimited. The month is inclusive at its start and exclusive at the next month start. The current Enrollment supplies eligibility and plan on every create. Premium-to-Basic preserves history and blocks further creates when already at 10. Deletion frees a slot; text edits remain allowed at the limit. Client/provider IDs and created_at are immutable on updates; HTTP ownership/time come from the signed-in client and server.

Providers read only entries attributed to themselves for currently enrolled clients. Removing an enrollment revokes reads and new creates immediately, preserves client history and does not reset usage; re-adding the pair restores only that provider's attributed history. Non-seed legacy NULL-provider rows remain client-only and excluded from quotas. Synthetic seed slots are explicitly attributed to valid pairs.

Backend create accepts provider_id. The existing text-only browser path defaults only when exactly one current enrollment exists; zero or multiple providers without provider_id return ordinary validation errors (422). A browser provider selector, quota display and multi-provider form creation are deferred. No plan-management or provider-account-deletion feature is added.

JournalEntry model create validations check current enrollment/plan and count entries directly by client_id, provider_id and current month interval. Before create validation, SELECT FOR UPDATE locks the existing client row. Rails save/save! hold that lock in the same transaction through validation, count and insert; valid? alone is no reservation. This stable row survives enrollment removal/re-addition. It serializes all creates for that client, including different providers, an accepted cost for this small app. Explicit bulk SQL and validation-skipping maintenance bypass model rules and are outside normal application create paths.

Provider has direct journal ownership; current_journal_entries additionally filters current membership for the standalone interview query. Pundit scopes and record predicates independently enforce both attribution and membership, using PostgreSQL rather than display caches. Keep query-local ordering and the useful client index; pair/month and provider-feed indexes serve different access paths. The provider foreign key has no delete cascade, so account removal cannot silently destroy client history.

Keep provider_id nullable for preserved legacy data; require provider in new-record model validation. The schema migration never guesses legacy attribution. Manual demo seeds alone fill their established client/timestamp/ordinal slots, preserving IDs, edited text and timestamps. New historical seed rows use the bundled Rails time helper to validate at their intended month; seed-only attribution of existing NULL slots updates only provider_id. Six explicit Basic demo pairs cover previously unassigned clients with history, bringing enrollments to 206. No real/manual plan is changed. See [demo construction](../demo.md).
