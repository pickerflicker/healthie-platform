# Off-white calm interface

PIC-287 implements Steven's approved Off-white calm direction from the durable [Linear design pack](https://linear.app/pickerflicker/issue/PIC-287/implement-off-white-calm-ui-across-healthie-with-tailwind-css-daisyui). Archive SHA-256: `e1504a9c1e317af9997098c3552f94a7eaa5406694b97563ad686b1c977589a0`. The archive's index, lookbook and five boards define the visual reference; its fictional records and temporary interactions are not application code.

Rails ERB, Propshaft, Devise, Pundit, importmap, Turbo and Stimulus remain in place. There is one `off-white-calm` daisyUI theme in `app/assets/tailwind/application.css`. Tailwind scans views, helpers and controllers explicitly; generated `app/assets/builds/application.css` stays ignored. Do not restore global `nav`, `header`, `main` or form styles from the former stylesheet: nested navigation and dialogs have separate component boundaries. Desktop uses a sidebar; mobile uses compact role navigation. All addressable journal and workspace routes retain their URLs.

Canvas `#fafbf8`, surface white, primary `#306450`, sage `#e1ebdb`, peach `#f8eade`, text `#2e4039` and secondary text `#647169` match the pack. Semantic feedback colors do not represent medical information. Manrope and Lora variable fonts are bundled under `app/assets/fonts`, with `font-display: swap` and system fallbacks. Their SIL Open Font Licenses are in `vendor/licenses`; source is the official [Manrope](https://github.com/google/fonts/tree/main/ofl/manrope) and [Lora](https://github.com/google/fonts/tree/main/ofl/lora) distribution. Decorative symbols use ordinary font glyphs.

## Build and local commands

After `mise install` and sourcing `script/native_bundle_env`, run `mise exec -- bin/bootstrap` (installs npm packages and compiles CSS), then the existing local stack commands. `mise exec -- bin/dev` builds and watches CSS alongside native Rails. `mise exec -- bin/preview` installs locked packages, builds CSS and rebinds the shared Compose web service; run it again after visual changes when using the container preview. Direct `bin/rails server` users must first run `npm run build:css`, or use `bin/dev` for continuous recompilation.

`bin/check` and `bin/acceptance` build CSS before their suites. Run them sequentially because they share the isolated `healthie_test` database. CI uses these same commands. `rails assets:precompile` invokes `css:build` automatically and requires Node plus installed npm dependencies. The production and development Dockerfiles have a separate Node build stage. Production provides a build-only placeholder database URL (no connection/service required), copies compiled output into the Ruby image and sets `HEALTHIE_CSS_PREBUILT=1` only for its asset-precompile step; Node is absent from the final image. Compose's source bind mount uses the host build from `bin/preview` (or `bin/bootstrap` before `bin/stack up`). No runtime browser CDN/compiler is used.

Public 400/404/406/422/500 pages intentionally duplicate a tiny self-contained stylesheet and system fonts so asset failures do not hide recovery. The 406 page links to an external browser download, avoiding a sign-in loop on unsupported browsers.

## Dependencies checked 2026-10-20

- [npm Tailwind](https://registry.npmjs.org/tailwindcss/latest), [CLI](https://registry.npmjs.org/@tailwindcss/cli/latest) and [Tailwind upstream release](https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.3.3): latest stable **4.3.3**, exact pins for reproducible builds. Use the CLI, CSS `@source` and v4 plugins with [modern browsers](https://tailwindcss.com/docs/compatibility); no framework upgrade.
- [npm daisyUI](https://registry.npmjs.org/daisyui/latest) and [upstream release](https://github.com/saadeghi/daisyui/releases/tag/v5.7.50): latest stable **5.7.50**, exact pin; compatible with Tailwind 4 via [the plugin installation](https://daisyui.com/docs/install/) and [custom themes](https://daisyui.com/docs/themes/). Its CSS-only components do not replace Hotwire behavior.
- Node container: **22.23.3-bookworm-slim**, current Node 22 patch from the [official image](https://github.com/nodejs/docker-node/blob/main/22/bookworm-slim/Dockerfile) and [Node releases](https://nodejs.org/dist/index.json). Latest stable overall was 26.12.0. Choosing the maintained Node 22 line is a deliberate compatibility/reproducibility tradeoff with this repo's existing Node 22 mise/CI toolchain, rather than a hard Tailwind limitation. A coordinated runtime/CI upgrade would permit the newer major; local mise stays unchanged. Node is build-only in production.
- `npm audit` reports an upstream unpatched `braces <=3.0.3` stack-exhaustion advisory via Tailwind CLI → Parcel watcher → micromatch. npm's latest braces is 3.0.3; no compatible patched release was available. This affects build/watch tooling processing glob patterns, not shipped app JavaScript. Do not apply `npm audit fix --force`, which proposes replacing the selected toolchain. Recheck upstream when updating the build dependencies.

## Behavior and validation

Shared native dialogs identify the selected record in server-rendered markup. Cancel and Escape restore focus; confirmed deletion submits the record's ordinary authorized Rails form. Turbo disables the submitting control and announces pending feedback; server validation remains authoritative. A small selection-display controller keeps the full selected provider name/credentials readable below the native selector, including after selection changes; the server still decides eligibility and ownership. Journal and enrollment query ordering, scalar Redis projection, credentials catalog and authorization are unchanged. Role denial now renders a themed HTML screen with its existing 403 response; concealed records retain 404 and a generic recovery screen.

`test/browser/calm-ui.spec.js` covers cancel/Escape/focus, selected-record persistence, validation recovery, pending duplicate-click prevention and asset/JavaScript-independent errors. `calm-layout.spec.js` exercises real test-owned populated pages with long content at 1280/390/320px. Existing browser journeys still own their data, explicitly switch users, verify credentials, relationship order and direct access after removal. Demo seeds remain exclusively for manual review. Generated screenshots/reports belong in ignored output and the single PR QA comment.

Relationship lists reserve a shared desktop plan column and equal-width, single-line Basic/Premium badges. The layout suite checks both roles at 1024/1280/1440/1920px for aligned badges with contained text, alongside the existing mobile reflow checks. Visual QA must inspect actual desktop captures as well as page overflow: a badge label can escape its surface without increasing the document width.
